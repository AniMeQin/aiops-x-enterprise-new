# 项目章程

## 目标

AIOps-X Enterprise 面向企业 IT 运维团队，形成“资产发现—遥测汇聚—告警关联—事件处置—审批执行—验证回滚—审计复盘—知识沉淀”的可追踪闭环。

第一原则是证据真实：生产页面、API、Agent、AI 诊断和任务结果都不得由模拟数据或固定成功响应驱动。

## 架构边界

- 控制平面：FastAPI 模块化单体，负责身份、租户、CMDB、告警、事件、自动化策略、审批与审计。
- 数据平面：Edge Agent、采集器、执行器、扫描器、AI Engine 独立进程和身份。
- 基础设施：PostgreSQL/pgvector、Redis、NATS JetStream、MinIO；Prometheus、Loki、Tempo 等通过适配器接入。
- 客户端：Vue 3 管理台只读取版本化 API，不嵌入业务真值。

## 第一阶段成功标准

1. Compose 可启动基础设施和应用，服务提供真实 `/health`、`/ready`、`/metrics`。
2. 管理员可登录并建立租户、项目和资产。
3. Linux Agent 可一次性令牌注册、mTLS 通信、心跳与能力上报。
4. Alertmanager 测试告警可归一化、指纹去重并形成事件时间线。
5. 经审批的 R0 磁盘巡检可执行、保存结果、关联事件并写入追加式审计日志。
6. 有 AI 配置时只基于证据生成结构化摘要；无配置时明确不可用。
7. 关键模块单测覆盖率目标不低于 80%，迁移、合约、集成和 E2E 可重复执行。

## 非目标

第一阶段不建设大规模微服务、自研时序/日志/图数据库、完整 Kubernetes/数据库修复、破坏性自动化或机器学习训练平台。

## 角色与责任

- 产品与运维负责人：验收闭环、风险策略、维护窗口和 Runbook。
- 架构/开发：领域边界、契约、实现、迁移和测试。
- SRE：可观测性、容量、备份恢复、SLO 与演练。
- 安全/合规：身份、密钥、审批、GxP 隔离和审计复核。
