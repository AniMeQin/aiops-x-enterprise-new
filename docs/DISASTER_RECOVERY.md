# 灾难恢复

目标口径：控制面 PostgreSQL RPO 不高于 15 分钟、RTO 不高于 4 小时；审计归档和报告对象使用对象锁及异地复制。真实目标值以企业基础设施能力和最近一次演练证据为准，不以文档值冒充已达成。

每季度使用 `scripts/backup/dr-exercise.sh` 恢复到隔离 `_dr` 数据库，随后以 Helm digest 部署同一版本，依次验证 Vault/Secret Provider、迁移版本、登录、M1、M2、告警—事件—任务、审计链完整性、报告下载和 WORM 对象。演练失败时不得切换生产流量。

恢复顺序：DNS/证书与 Vault → PostgreSQL → MinIO → NATS/Redis → API/Worker → AI Engine/Web → Edge Agent 重连。切换和回切都必须生成时间戳、镜像 digest、备份哈希、RPO/RTO 和审批人证据。

## 目标（待业务确认）

- 建议初始 RPO：业务数据库 15 分钟，附件 24 小时。
- 建议初始 RTO：控制平面 4 小时，完整遥测检索 8 小时。

以上为规划假设，不是当前已验证承诺。

## 流程

1. 宣布事件并冻结非必要变更。
2. 确认影响范围、数据最新恢复点和凭据安全。
3. 在隔离环境恢复 Secret Provider、数据库和对象存储。
4. 使用固定镜像和配置启动控制平面，不自动执行任何 Runbook。
5. 验证租户隔离、身份、CMDB、告警、事件、任务和审计完整性。
6. 受控切流，持续观察并保留原环境回滚路径。
7. 完成审计和复盘。
