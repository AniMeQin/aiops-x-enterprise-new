# ADR-0001：模块化单体控制平面与独立数据平面

- 状态：Accepted
- 日期：2026-08-12

## 背景

平台包含身份、CMDB、告警、事件、自动化、审批、AI 与审计等强关联领域，同时 Edge Agent、采集器和执行器有不同的网络和安全边界。

## 当前问题

若首阶段直接拆成大量微服务，将引入分布式事务、部署、追踪和版本协调成本；若所有能力放入一个无边界进程，又会使采集/执行权限进入 Web API。

## 可选方案

1. 全量微服务：隔离强，但第一阶段复杂度和交付风险高。
2. 单体应用包含 Agent/执行器：部署简单，但权限边界不可接受。
3. 模块化单体控制平面 + 独立数据平面：在领域内保持本地事务，对高风险进程做物理隔离。

## 决策

选择方案 3。控制平面内部通过应用服务、领域事件和版本化契约协作；Web、Worker、AI Engine、Edge Agent、采集器和执行器是独立部署单元。

## 风险

- 模块边界可能被直接 ORM 查询侵蚀，需要代码评审和架构测试。
- 单个数据库可能成为容量瓶颈，需要按模块监控与索引治理。
- 独立进程仍需可靠事件、幂等和可观测性。

## 迁移成本

当某模块达到独立扩缩容或合规边界时，可用现有应用接口和事件契约抽取服务，迁移数据所有权并双写/回放验证。

## 回滚方法

如独立数据平面导致早期部署不可接受，可保持相同代码和身份边界，在同一 Compose/Kubernetes 集群部署；不得把高权限执行代码合并进 API 进程。
